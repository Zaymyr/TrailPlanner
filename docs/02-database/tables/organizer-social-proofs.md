# organizer_social_proofs

## Purpose

`organizer_social_proofs` stores the administrator-curated, edition-scoped proof cards published on `/organisateurs`. It combines optional consented organizer copy with a durable snapshot of aggregate RaceBook usage. The public landing summarizes the first ordered proof in its conversion hero, independently of the now self-contained phone demonstration, then gives the complete published selection a dedicated highlighted surface with semantic metrics and an optional visually distinct testimonial. The landing never queries PostHog directly and never receives runner identities.

## Key Concepts

- One edition has at most one proof row.
- Draft rows are never rendered publicly.
- Publishing requires an explicit authorization confirmation and a captured analytics window.
- `unique_readers` means distinct PostHog persons observed through `racebook opened`; it is an estimate, not the event's official participant count.
- `total_opens` counts successful RaceBook opens in the same window.
- The snapshot begins at the earliest attached format's first publication and ends at the earlier of today or fourteen days after the edition end date.
- Internal/test PostHog persons remain excluded by the shared organizer analytics query.

## Columns

| Column | Type | Rules | Meaning |
| --- | --- | --- | --- |
| `id` | `uuid` | primary key | Proof identifier. |
| `edition_id` | `uuid` | unique, non-null FK | Canonical edition being featured. |
| `status` | `text` | `draft` or `published` | Public visibility state. |
| `display_order` | `smallint` | 0–999 | Lower values render first. |
| `quote_text` | `text` | nullable, max 1,000 chars | Consented organizer testimonial. |
| `quote_author_name` | `text` | nullable, max 160 chars | Public attribution name. |
| `quote_author_role` | `text` | nullable, max 160 chars | Public attribution role. |
| `consent_confirmed_at` | `timestamptz` | required when published | Admin confirmation that the reference may be published. |
| `unique_readers` | `integer` | non-negative | Snapshot of estimated unique RaceBook readers. |
| `total_opens` | `integer` | at least `unique_readers` | Snapshot of successful RaceBook opens. |
| `analytics_from`, `analytics_to` | `date` | both null or valid ordered pair | Inclusive measurement window. |
| `analytics_captured_at` | `timestamptz` | paired with window | Snapshot generation time. |
| `published_at` | `timestamptz` | required when published | Current publication time for stable secondary ordering; cleared on unpublish. |
| `created_at`, `updated_at` | `timestamptz` | non-null | Audit timestamps. |
| `created_by`, `updated_by` | `uuid` | nullable Auth FK | Trusted admin audit references. |

## Foreign Keys

- `edition_id -> race_event_editions.id on delete cascade`
- `created_by -> auth.users.id on delete set null`
- `updated_by -> auth.users.id on delete set null`

Deleting an edition removes its acquisition proof. Deleting an administrator account preserves the proof and clears only the audit reference.

## Indexes

- Unique `edition_id` enforces one editorial proof per edition.
- Partial `(display_order, published_at desc) where status = 'published'` supports the landing query without indexing drafts.

## RLS Policies

RLS is enabled. `public`, `anon`, and `authenticated` have no privileges and no policies. `service_role` has explicit CRUD grants. Admin routes must verify trusted Auth `app_metadata` before using the service role. The public landing performs a server-only, explicit-column read and returns only published presentation fields.

## Business Invariants

- A published row must have consent, a complete analytics window, capture time, and publication time.
- Attribution fields cannot exist without a quote.
- Analytics values are generated by the server; the admin form cannot type or override them.
- The admin edition picker filters the already authorized response locally by trail name, year, and location; changing the search does not broaden the server read or mutate proof data.
- Drafting or depublishing never deletes a snapshot, so an administrator may review and republish it later.
- A missing or failed PostHog response blocks a requested refresh/publication rather than manufacturing zero usage.

## Common Queries

```sql
select edition_id, unique_readers, total_opens, quote_text
from public.organizer_social_proofs
where status = 'published'
order by display_order asc, published_at desc
limit 3;
```

## Gotchas

- Do not label `unique_readers` as official participants. PostHog identity, consent and device behavior make it an estimated readership measure.
- Do not call PostHog from the landing request. Refresh the persisted snapshot from the protected admin route and invalidate the landing cache only after the database write succeeds.
- Do not expose drafts or audit ids through an anonymous Data API grant. Public presentation remains server-only and allowlisted.
- The event favorite count is event-scoped current stock and is intentionally not stored in an edition proof.
- The hero and highlighted section intentionally reuse the same first ordered snapshot; do not compute a separate or fresher metric in the client.
